A patch release on top of `v0.13.2`. Music, Books and Adult library support is removed, and the migration behind it drops twelve tables. Read the upgrade notes before pulling; back up first.

## Server

### Library

- Music, Books and Adult library types are removed: the UI, the contexts and schemas, and the type enums are all gone.
- A library path stored in the database with one of those types converts to `mixed` and is disabled, which drops it out of the Library Paths page entirely. Its media files are untouched. Re-enable it from Settings to have it scanned as a regular video library.
- A library path declared as one of those types in `config.yml` or through environment variables is accepted rather than rejected. It is coerced to an unmonitored `mixed` library that is not scanned, and a warning naming the path is logged at startup. This is deliberately different from the database case: configuration is re-read on every boot, so a config-declared path stays visible and coerced rather than converted, and only editing the file changes it. Remove the entry whenever convenient.
- Search results in Torznab Audio, XXX and Books categories no longer auto-assign a library. They prompt you to choose one instead.

### Data safety

- The twelve tables behind Music, Books and Adult (`playlist_tracks`, `music_files`, `playlists`, `tracks`, `albums`, `artists`, `book_files`, `books`, `authors`, `adult_files`, `scenes`, `studios`) are archived to NDJSON, one file per table, before they are dropped. Nothing is deleted without a copy written first; if archival fails, the migration raises and the tables stay in place.
- The archive is written to the first writable location, in order: `MYDIA_DATA_DIR` if set, the directory holding the SQLite database (`/config` in the default container image), `/data` if it exists, then `priv/data` as a last resort. The chosen path is logged at startup, so the log is the authoritative answer for any given install.
- On PostgreSQL, if neither `/config` nor `/data` is mounted and `MYDIA_DATA_DIR` is unset, the archive falls back to `priv/data`, which does not survive an image pull. Set `MYDIA_DATA_DIR` before upgrading if you want to keep the archive.
- The archive directory is never cleaned up automatically. Delete it yourself if you don't want it.

## Upgrade notes

Back up first.

1. **Twelve tables are dropped**: `playlist_tracks`, `music_files`, `playlists`, `tracks`, `albums`, `artists`, `book_files`, `books`, `authors`, `adult_files`, `scenes`, `studios`. Every row is archived to NDJSON first; see Data safety above for where the archive lands.
2. **A database library path typed music, books or adult converts to `mixed` and disabled.** It disappears from the Library Paths page and its files are left alone. Re-enable it from Settings to scan it as a regular video library.
3. **A config-declared library path of one of those types keeps working, coerced.** It boots as an unmonitored `mixed` library and logs a warning naming the path; it never scans until you change or remove the entry.
4. **Torznab search results in Audio, XXX and Books categories no longer auto-assign a library.** Pick one when prompted.
5. **The archive is not cleaned up automatically.** Remove the `archives/mba-<timestamp>/` directory the startup log names once you are satisfied you do not need it.
