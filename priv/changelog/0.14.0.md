200 pull requests since v0.13.2, across five betas and fifteen days. Most of that went on the import rewrite, which shipped in beta.1 and then spent four more betas being corrected by operators running it against libraries far messier than mine. That was the point of the long beta, and the correctness section below is what it bought.

The middle of the cycle is where the features are: sidebar sections, preset collections, a trash you can actually see, one player driving another over p2p, and HLS seeking that stopped tearing down the whole pipeline.

Read the upgrade notes before pulling this. Music, books and adult are gone, remote access turns on for existing installs, and there are 37 migrations, two of them irreversible. Back up first.

## Import

- The import run moved out of the browser. It lives in Oban on its own `imports` queue and works in two phases: a scan commits a `media_files` row per file with no HTTP at all, then a match phase caches a candidate per file and links confident matches. Closing the tab, a disconnect or a deploy no longer loses progress, and the database is the cursor, so Continue is a fresh run over the same path. Matching groups a batch by normalized title and warms the cache on one file before fanning out, so twelve episodes of a season cost one relay search where they used to cost ten (#472, #480, #494, #497)
- Review works on folders. A few thousand unresolved files collapse to a few dozen folder groups arranged as series, seasons and episodes, and actions apply to the whole group: change the match, reversible ignore, create a show from the folder for media no provider carries, and bulk accept. Selection is a filter predicate, so "select all" stopped blowing past the adapter's bind-parameter cap. Match policy is one number, the 0.85 link threshold shared by the review bands and the ingest path (#482, #493, #495)
- Discovery and maintenance run on separate paths. `auto_import` gates discovery only, `media_files` requires a parent through a CHECK constraint on both adapters, and a path-keyed `import_candidates` table replaces `media_file_match_candidates` and `import_groups`. A scan builds the import inbox and the flag actually gets read, so a library stops sitting on hundreds of matched orphans while `/import` claims there is nothing to review. An accepted import can create episode rows a provider is missing, bounded by a plausibility check, and adopts them in place once the provider catches up (#628, #600, #614, #663)
- Accept and re-match are durable background work again. An earlier refactor deleted both Oban workers and replaced neither, so the review page promoted candidates synchronously inside the LiveView process: "Import all" over a fresh library meant one sequential relay round trip per group inside a single `handle_event`, no retries, nothing surviving a closed tab. The intent lives on the candidate row and a worker keyed on the library path finds its own work (#647)
- `ENABLE_IMPORT_LISTS` gated a nav link and nothing else. The route, the 15-minute cron and the sync jobs all ran whatever it was set to. An audit turned up eight bugs behind it, including a failing list that stayed permanently due and re-enqueued every 15 minutes at roughly 96 relay hits a day, and a custom URL fetched with no scheme or destination check. The flag gates the feature for real, requests are limited to http and https against public addresses with every redirect hop rechecked, and with that fixed the default flips to on (#665)

## What the beta found

Everything in this section came from operators running beta.4 and beta.5 against real libraries.

- "Re-scan files" could delete your media. It decided a file was gone by diffing path strings against one inferred directory, then handed every unmatched row to the trash store, which found the file present and moved the bytes out of the library. The toast reported a clean sweep while it happened. Three separate conditions produced that false verdict, and a shared on-disk guard covers all three. Underneath sat a second defect: two `media_files` rows could describe one physical file, which is the extra row re-scan was reading as missing. A unique index on library path plus relative path closes that, and a migration folds existing duplicates onto one winner (#658)
- Re-enrichment had been overwriting `monitored`. One attrs map served both the create and the update path with `monitored: true` hardcoded, so any scan promoting a file for an item untouched for more than an hour reset the operator's choice. It stayed invisible because the change tracker recorded title, original title and year, nothing else. Monitored changes land in item history and the activity feed (#659)
- Jaro-Winkler scored two unrelated titles at 0.897 on a shared first word. On a live instance five season packs of one show attached to a title the library held no copy of, at 0.886. The matcher rejects candidates whose words the release title does not cover, the binding tiebreak stays out of the stored confidence, and a file can be sent back to Review from its details in one transaction (#669)
- A season pack could finish with its last episode marked missing while the content sat on disk inside a combined `S01E09E10` file. `media_files.episode_id` is a single foreign key, so the matcher kept the first episode number and dropped the rest. A join table carries the links, and a migration re-reads existing filenames to add back what was discarded (#679)
- An external-id duplicate tie breaks on id, so the winner is stable when two rows share an `inserted_at` timestamp (#632)

## Trash and duplicates

- Trash was fully built on the backend and completely invisible. Files moved to `.mydia-trash` and were purged after 30 days, with no way to see what was in there, restore something, or reclaim the space early. `/admin/config/trash` lists it newest first, with filter chips, per-row restore and permanent delete, and bulk actions running through an Oban worker so they survive a closed tab. `media_files` gains a `trashed_reason` stamped at all seven call sites. Retention moved into the layered config, and manual file deletion routes through the trash by default (#666)
- Settings > Duplicates reviews items holding more than one active file. It is mostly a refusal engine: on a real library 518 episodes and 39 movies hold multiple files, and most are misidentification, one file registered twice, or bonus features. Anything it cannot prove is the same content is surfaced as needing attention, with the first failing check given as the reason. Files rank against the item's quality profile, falling back to resolution, then bitrate, then size, then codec, because a low-bitrate av1 re-encode is not an upgrade over a high-bitrate source. Nothing runs on a schedule and there is no new table (#520, #521, #522)
- Every per-group control on that page only changed what was marked, and the one button that moved files ran across the whole library, so clearing a single item meant marking every other group Keep first. Each group carries its own trash button with an Undo toast holding the run's file ids (#664)

## Discover, adding and requests

- Discover is the one place to find and add media, and the separate Add and Request pages are deleted. Two bugs surfaced while consolidating: adding from Discover never queued an indexer search, and `media.auto_search_on_add` was declared, documented, loadable from the environment, and read by nothing in `lib/`. `Mydia.Media.AddDefaults` resolves library, quality profile, monitoring, season monitoring and search-on-add through an explicit choice, then the user's preference, then the instance setting, then a fallback (#649)
- Adding a title took two dialogs, and the second was reachable only from Discover, leaving the dashboard and the media detail page with a library choice and nothing else. A single-library install never saw the caret at all. The picker is merged into Configure Before Adding, and two authorization gaps found along the way are closed (#676, #678, #536, #537)
- A production add failed with "Media not found: 280619". The relay routes every TV search to `/tvdb/search`, but the card shipped the resulting id in a param named `tmdb_id`, and a TVDB id that happens to exist on TMDB would have added the wrong show. The follow-up makes the provider travel with the id as a tagged `Mydia.Metadata.Ref`, parsed once at the web boundary, which closed the same bug in the recommendations rail and in import lists where it ran in the opposite direction (#672, #677, #456)
- Approving a guest's request offered one optional notes textarea and decided everything else, hardcoding `monitored: true`, leaving the item with no quality profile, and never queuing a search. `docs/using/how-to/manage-users.md` has promised "download begins" since it was written. The approve modal carries the same five controls as Configure Before Adding, prefilled from the approving admin's defaults (#689)
- Adding a title that someone had already requested left the request sitting in the pending queue. Matching pending requests are approved and linked to the media item on create, attributed to whoever performed the add, or marked approved automatically when a scanner did it (#691)
- With Hide in library on, Discover opened showing four or five titles instead of twenty. The backfill guard only fired when filtering emptied a page outright, so a page keeping four of its twenty satisfied it and the chain stopped on page 1. Loads aim for a target count instead (#684)
- Requests carry posters and a detail popup, the activity feed and title timeline are scoped for guest accounts, clicking a poster in a recommendations rail or franchise strip opens the same dialog Discover uses, and the Add to Library button stopped wrapping out of its pill (#556, #555, #674, #673)

## Collections and sidebar sections

- Any smart collection can be pinned to the sidebar as a section. Sections render through the media index, which hands them the whole TV Shows toolbar: filters, sorting, selection, batch actions. Mark one exclusive and it claims its categories away from Movies and TV, which is what answers the long-standing request for an Anime destination without handing every instance a fixed Anime section. Pins are per user. Exclusivity is derived from the rules on every read (#644)
- Four sidebar-section defects from a running instance: an undismissable excluded-items banner on every Movies and TV visit, an anime nudge that kept asking after you accepted it, icons that never emitted CSS, and a re-pin that wiped a customized icon (#654)
- Sixteen preset smart collections grouped into decades, genres, highlights, series and language, each showing a live count of matching items in your library, added in one click. Smart rules could already express most of this and almost nobody knew, because the only way in was an empty condition builder. The rules gain a `within_last` operator for relative dates, and `not_in` works for language and status (#667)
- Editing a smart collection showed `Select...` in place of the value the rule stores. Multi-value operators joined their stored list into one string before comparing it against one option at a time, and the option list came from a library scan that omits any stored value the library has stopped matching. A metadata field in the same dialog would crash it outright (#652, #615)

## Remote access, pairing and devices

- Pairing is end-to-end encrypted. The server generates the claim code locally and derives an Argon2id seed from it. The relay receives a blinded lookup key and a ChaCha20-Poly1305 sealed blob holding the node address and instance id, and can read neither. Before this it held both halves of the secret, so it could pair itself as a device or substitute an address. Derivation and sealing live in one Rust module in `mydia_p2p_core`, reached from Elixir through Rustler and from Dart through flutter_rust_bridge, with a pinned known-answer vector guarding the parameters. The p2p path also had no guess limiting, so codes could be ground against roughly 30 bits at whatever rate the server answered (#513)
- Connecting a player is a user action. Every signed-in account gets a `/devices` page listing its own paired players with real online status, pairing codes, revoke and remove, and download links for Android, iOS, macOS, Windows and Linux. The Remote Access toggle was read in exactly one template and nowhere else, so switching it off still left a node dialing the relay, still allowed pairing, and still served media to every paired device. It gates claim codes, p2p pairing, media reads and GraphQL, and the keypair path defaults under `MYDIA_DATA_DIR` (#510, #496)
- One player can discover, adopt and drive another over iroh. Mydia targets appear in the same picker as Chromecast and DLNA. Picking a target that is already playing adopts that session instead of restarting the film, Push hands over the local position and tracks and only stops local playback once the target confirms, and Pull reads the target's exact position before stopping it. A banner shows what other paired players are playing, holding at most three live connections. Answering commands is a settings toggle, on by default, re-checked per request. The end-to-end test for this is still quarantined: every piece has unit coverage and the integration layer does not run, which is written down in the test file (#524, #526, #527, #528)
- Two players on the same account could not see each other, with nothing in the picker and no error. Discovery is server-mediated through a posted iroh node id, and a device without one is filtered out of every roster. iOS had never registered once. Registration is reconciled from watched inputs, so a device that misses its first attempt still lands (#648)
- A player connected to production showed its connection dropping and reconnecting while continuing to work. Two defects produced that. A stale connection timing out announced `Event::Disconnected` for a peer still serving requests on a newer connection, and a resolver raising inside `Mydia.P2p.Server` killed the whole host, which happened three times in seven days. GraphQL, pairing and `read_media` run off the GenServer under a bounded task supervisor (#681)
- The unauthenticated `read_media` p2p request is retired, server and player each declare the oldest counterpart version they work with over a public `serverCompatibility` GraphQL field, and pre-iroh leftovers are gone with iroh-relay held at v1.0.0 (#695, #470, #509, #498)

## Streaming and subtitles

- Far scrubs used to tear down the whole playback stack and rebuild it behind a full-screen spinner, so after resuming a movie at 45 minutes every backward seek restarted it. The playlist is computed up front from the media duration and served as a complete VOD playlist, with FFmpeg as a movable window underneath addressed by absolute segment index. A segment request resolves to one of three things: serve a file already on disk, park the caller until the encoder reaches it, or relocate the encoder. Requests are serialised through the session, so the several parallel requests a player fires on one seek trigger exactly one relocation (#638)
- Every windowed HLS session crashed about 60ms in. The transcoder's segment callback was wired for both playlist modes, and a window session has no transcode window to mark ready, so the first report killed it (#639)
- The player probes a device profile, sends it on every request and trusts the server's per-device direct play answer, over the p2p GraphQL transport too. Profile validation covers the whole profile, HLS_COPY is never offered for a stream the client already rejected, and a leading HLS_COPY candidate stopped counting as direct-playable (#541, #563, #564, #566)
- Subtitle tracks are first-class, with their own settings rows, per-episode placement on the file row, and automatic re-sync against the media file's own audio. The subsync cdylib builds on musl, which unbreaks the Alpine images (#585, #588, #592, #589)
- Subtitle downloads work. The stored format is read out of the file's own content, the download button no longer takes the media page down with it, auto-download shares the manual path, and malformed and negative result indexes are rejected. Search results rank by release-name match against the file on disk, with the score explained as a factor breakdown, and the dialog got a mobile shell (#532, #545, #546, #467)
- Playing a file with no subtitle tracks, the subtitles button was greyed out with a "No subtitles" tooltip, which is exactly the moment a viewer wants subtitles. Everything behind it already shipped: the sheet renders a Search online row that runs the real provider search and download. One line locked the door. The button also stays alive in direct play on iOS (#682, #548)
- Chromecast gets subtitles over both direct and p2p routes, and the audio track is picked by language preference with the choice remembered (#462, #449)
- Continue Watching named a season three episode for a viewer two episodes into season one, because a nine-second progress row left behind three weeks earlier counted as being partway through. A resume point has to clear two minutes or 10% of the episode, the same bar the home rail already used to decide the show belonged there (#680)

## TV, metadata and downloads

- Oversized TV seasons can be split using TVDB's alternate season orderings, turning a single 170-episode season into 51, 51, 52 and 16 under DVD ordering. Switching is lossless: file links, downloads, watch history and per-episode monitored flags all survive. Episodes carry `absolute_number` and `provider_episode_id`, the upsert keys on provider identity, seasons above 50 episodes render in collapsible labelled ranges, and only the orderings TVDB actually publishes for a show are offered (#486, #499, #504, #517)
- Metadata refreshes reach episodes. The scheduled pass was skipping the episode leg outright, and its throttle applied to the manual refresh button too. TV monitoring stays in sync between presets and manual season toggles. Adding a show fetches every season and applies the preset afterwards; filtering the fetch by it had been leaving `"first"` and `"none"` shows with zero episodes in the database (#454, #447, #692)
- Movie extras are classified as extras. They used to show up as versions of the feature. Detection runs at scan time and again after analysis, demoting any file under half its movie's published runtime, with promote and demote controls and operator decisions that stick. The demote button also looked like a download button (#596, #623)
- Manual search survives a bad indexer. Results stream, so one dead indexer can no longer stall or blank the whole search, the indexer bar shows a search still running, and a result carrying a nil field is handled where it used to blank the whole list (#474, #479, #500)
- Cardigann search URL construction, redirects, failover and the connection test are repaired, after a user reported five passing connection tests and five failing searches. Session cookies stay scoped to a definition's own origins (#601, #606)
- A monitored show searched, ranked 100 results, selected a season pack, and never downloaded it. No download row, no error, nothing in the log. The download URL was fetched with redirects enabled and the redirect pointed at a `magnet:` scheme Finch rejects. Oban job failures are logged with their reason (#675)
- Cancelling a download no longer deletes source media, and one deleted mid-flight takes neither the jobs nor the LiveViews down with it. Trackerless `.torrent` files get public trackers added, which was killing real downloads, and `min_seeders` for automatic search is operator-configurable (#450, #505, #508, #440, #441)
- New per-client External torrents mode. A torrent adopted from the client that falls outside the policy lands in External, badged, and recorded as a `download.adopted` activity event, where it used to pile up in Issues. Transmission writes the configured category as a torrent label (#535)
- `Quality` stores a canonical HDR base plus a separate Dolby Vision profile, because HDR files had been scoring below SDR in quality profiles and a null `hdr_format` read as SDR. Separator-form HDR10+ is recognised, the DV profile fields are exposed over GraphQL, and a one-shot backfill recomputes HDR on files already in the library (#543)
- PreDVD releases stop resolving to the DVD source, a 1080p profile stops grabbing a 360p rip, and season packs match at show level with titles addable straight from the match dialog (#593, #635, #637)

## Upgrade notes

Back up first. Thirty-seven migrations, two of them irreversible.

1. **Music, books and adult are removed.** `library_paths` rows of those types convert to `mixed` and are left unmonitored, never deleted, because deleting them would cascade into real movie and TV media. Leave monitoring off on those paths. A `mixed` scan collects video extensions only and would classify everything else as deleted, which moves the bytes to trash. Twelve tables are dropped with every row archived to NDJSON first, written to `MYDIA_DATA_DIR` if set, then the SQLite database's directory, then `/data`, then `priv/data`. That last one does not survive an image pull, so set `MYDIA_DATA_DIR` before upgrading if you want to keep it (#471).
2. **The import split is irreversible by design.** Parentless `media_files` rows get backfilled into `import_candidates`, and orphan-only analysis (phash, probe metadata, generated blobs) does not come across. `auto_import` also changes meaning: it gates discovery of new files rather than linking them (#628).
3. **The duplicate fold is the other irreversible one.** It deletes the losing `media_files` rows outright, because a soft-trashed row with no trash metadata reads as legacy and would schedule your real files for deletion 30 days out. Rolling back lifts the unique index and nothing else (#658).
4. **`/import` may show work that was previously invisible.** The scheduled scan writes a match candidate for every file it cannot link, which it never did before, so orphaned files that have been invisible for months appear in review on your first scan. The scan's linking decision is unchanged (#472, #600, #628).
5. **Check your monitored flags once.** Re-enrichment had been resetting `monitored` to true since long before this release, so an item you deliberately unmonitored may have been switched back on. Nothing restores a flag already overwritten (#659).
6. **Remote access turns on for every install that already has a config row.** The old flag was never enforced, so a stored `false` records a click and says nothing about how the server behaved. Honoring it would cut off working remote players. `ENABLE_REMOTE_ACCESS=false` remains the hard off switch. Pairing is also no longer admin-only: any account can pair a player from `/devices`, and a paired device carries its owner's permissions (#510).
7. **Manual claim-code entry breaks against players that have not updated.** An older app typing a code at an updated server gets "invalid or expired code". Use the QR on the same screen, which works across versions. An updated player pairing with an older server falls back to the old unencrypted lookup. The relay serves both route sets through the transition, and the fallback comes out one minor from now (#513).
8. **Import lists default to on.** `ENABLE_IMPORT_LISTS` used to gate a nav link while the cron and the sync jobs ran regardless. A missing key now defaults to on and an explicit `false` still wins. Lists configured with auto-add start being honoured, and auto-added items are monitored, which hands them to the search workers. `IMPORT_LISTS_ALLOW_PRIVATE_DESTINATIONS=true` opts a NAS or container network back in (#665).
9. **`/add` and `/request` are gone.** Both are Discover, with no redirect, so old bookmarks 404 (#649, #676).
10. **Manual file deletion routes through the trash.** Deleting a file from the UI moves it to `.mydia-trash` and holds it for `TRASH_RETENTION_DAYS`, 30 by default. Files trashed before this release carry no reason and show as Unknown; there is no backfill, because the information to reconstruct them does not exist (#666).
11. **A season pack may gain episodes on first boot.** The relink migration re-reads existing filenames and links combined files such as `S01E09E10` to every episode they contain, so episodes that read as missing can flip to present with nothing downloaded (#679).
12. **Movie extras get reclassified.** A recurring worker demotes any file running under half its movie's published runtime. Promote anything it gets wrong and the decision sticks (#596).
13. **HDR files are re-ranked.** A file stored with a Dolby Vision or untagged HDR format may sort differently against your quality profiles, and a one-shot backfill runs at boot to recompute it (#543).
14. **`monitoring_preset` is dropped from `media_items`.** TV monitoring is derived from episodes, with only `monitor_new_seasons` stored (#447).
15. **PostgreSQL installs get column widening across the schema**, `varchar` to TEXT and int4 to bigint. Expect the migration to take longer on a large database (#448, #451).
