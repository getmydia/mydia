Connecting a player is a user action now, and the Remote Access switch finally does what it says. Read the upgrade notes before pulling.

## Server

### Devices

- Connecting a player is a user action now. Every signed-in account gets a Devices page listing its own paired players, with pairing codes, revoke and remove. It no longer takes an administrator to connect a phone.
- The Devices page links the player download for every platform: Android, iOS, macOS, Windows, and Linux as both a Flatpak repo and a tarball.
- `/admin/devices` redirects to `/devices`. The page it replaced only ever listed the signed-in administrator's own devices.
- Settings > Remote Access keeps the server side: the on/off switch, node ID, relay status and direct URLs.

### Remote access

- Remote access is on by default. Set `ENABLE_REMOTE_ACCESS=false` to keep the p2p node from starting at all.
- **The Remote Access switch now controls remote access.** It was previously cosmetic: it decided whether the pairing card rendered, while the p2p node ran and served every paired device regardless of its setting. Turning it off now refuses new pairings, media tokens and relay-tunneled requests. Paired devices are refused rather than revoked, so turning it back on restores them without re-pairing.
- Every existing install is set to enabled on upgrade, including those whose switch read off. That setting recorded a click, not how the server behaved, so honoring it now would have cut off players that were working. Turn it off after upgrading if that is what you want.
- A freshly paired device now receives the server's direct URLs. The lookup behind that field matched a return shape the function never produced, so the list was always empty and paired devices never learned the server's LAN addresses.
- The p2p keypair path defaults to a file under the data directory instead of being required. An install that never set `P2P_KEYPAIR_PATH` would otherwise have failed to boot once remote access defaulted on.

## Upgrade notes

1. **Remote access is enabled on every install.** If you had the Remote Access switch turned off, it is on after upgrading, and now it means something. Turn it off again from Settings > Remote Access if you want it off, or set `ENABLE_REMOTE_ACCESS=false` to stop the p2p node entirely.
2. **Pairing is no longer admin-only.** Any account, including guests, can pair a player from `/devices`. A paired device carries its owner's permissions, so it can do exactly what that account can do in the web UI and nothing more.
