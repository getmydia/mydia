# Translating the player

The player is translated with Flutter's `gen_l10n` and ARB files. The web UI
uses Gettext instead; see `lib/mydia_web/gettext/README.md`. Translators work
on Weblate (component `player`, see `TRANSLATING.md`). This file is for
developers writing player code.

## Where messages live

- `lib/l10n/app_en.arb` is the template. Every message needs a
  `"@key": {"description": "..."}` entry that tells a translator where the text
  appears. `test/l10n/arb_consistency_test.dart` fails without it.
- `lib/l10n/app_es.arb` and any other `app_<locale>.arb` are translations.
  Keep their keys in the same order as the template.
- `l10n.yaml` configures the generator. Its output, `lib/l10n/gen/`, is
  gitignored. `flutter pub get` and `flutter test` regenerate it. The release
  Dockerfile copies `l10n.yaml` for the same reason, and `.dockerignore` keeps
  a local `gen/` out of the build context. In devenv the
  `mydia:flutter` task re-runs pub get when the ARB files or `l10n.yaml` change,
  so a pulled translation update does not leave a stale `gen/`.
- Do not hand-edit non-English ARB files once Weblate owns them. Fix wording on
  Weblate, or your edit is overwritten by the next sync.

## Writing text

Import `package:player/l10n/l10n.dart` and use `context.l10n`:

```dart
Text(context.l10n.settingsSignOut)
```

- Keys are camelCase, `<area><Purpose>`: `loginServerUrlLabel`,
  `settingsSignOut`. Use the `common` prefix only for words used in two or more
  areas (`commonCancel`).
- One message per whole sentence. Never join translated pieces, word order
  differs between languages.
- Values are placeholders declared with a type in the `@key` entry. For
  example, a plural (the key here is illustrative):

  ```json
  "settingsDeviceCount": "{count, plural, one{{count} device} other{{count} devices}}",
  "@settingsDeviceCount": {
    "description": "How many devices are paired.",
    "placeholders": { "count": { "type": "int" } }
  }
  ```

  Keep the number in the `one` form too: some languages use it for 21, 31 and
  so on.
- Never translate media or user data, text sent by the server, `debugPrint` and
  log text, `Key('...')` values, or product names (Mydia, Plex, Jellyfin,
  Stash, TMDB, TVDB, Chromecast).
- A string that names a button or menu in the web UI must use the web's label
  in that language. See `loginTvStepOpenDevices` and its description.
- Code with no `BuildContext` (a controller, a service) does not call
  `context.l10n`. Take an `AppLocalizations` as an argument and let the widget
  pass `context.l10n` in.
- A new language needs its name in `localeDisplayName`
  (`lib/l10n/locale_names.dart`), written in that language. Without it the
  picker shows the language code.
- A regional variant (`app_pt_BR.arb`) needs its base language file
  (`app_pt.arb`) next to it, or gen_l10n fails `flutter pub get` and every
  build breaks. When Weblate adds a region-only locale, create `app_pt.arb`
  containing `{"@@locale": "pt"}`. `test/l10n/arb_consistency_test.dart`
  checks this.

## Converting a screen

Only the paths listed in `convertedPaths` in
`test/l10n/untranslated_text_test.dart` are checked. Converted so far:
`screens/settings/`, `screens/login_screen.dart`, the language picker and
`core/startup/startup_error_app.dart`.

1. Add the screen's path to `convertedPaths` and run
   `./dev flutter test test/l10n/untranslated_text_test.dart`. It lists every
   literal.
2. Move each one to `app_en.arb` with a description, then use `context.l10n`.
3. Add the Spanish only if you can write it well. Otherwise leave it out and
   Weblate fills it in; a missing translation shows in English.
4. `// l10n-ignore` on a literal's first line skips it, for text that is not
   translatable (a format string, a code sample). Say why in the same comment.

The scanner reads string literals passed to `Text(...)` and to named arguments
such as `label`, `labelText`, `hintText`, `helperText`, `errorText`, `title`,
`subtitle`, `tooltip`, `message`, `semanticLabel` and `text`. It does not see
ternaries (`a ? 'On' : 'Off'`), `??` fallbacks, concatenation, or a literal
passed positionally (toast helpers, for instance). Convert those by hand when
you convert the screen.

Not converted yet: `login/login_controller.dart` (it matches error text as
strings) and the leftovers in core: the enum labels (`ThemePreset`,
`GlassMaterial`, `SubtitleSize`, `UpdateTrack`, quality) and
`formatRelativeTime` (`lib/core/format/relative_time.dart`, used by
`devices_screen.dart`), which still returns English.

Widget tests that pump a converted widget need the delegates on their
`MaterialApp`, or `context.l10n` throws:

```dart
MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: ...,
)
```

## How the language is chosen

`localeSettingProvider` (`lib/core/settings/locale_setting.dart`) holds a
`Locale?`. `null` means follow the device, which is the default. A choice is
stored under `interface_locale`, and the picker is a row in Settings,
Appearance. A stored tag the app no longer ships falls back to the device
language. The provider is hand-written because
riverpod_generator cannot print `Locale`.

The web player a Mydia instance serves at `/player` follows the web UI
instead: `PlayerController` injects the request's resolved Gettext locale as
`window.mydiaConfig.locale`, and `hostLocaleProvider` maps it to a shipped
player locale (exact match, then the bare language, then English, which is
what the web UI shows for untranslated text). When it is present the stored
choice is never read, because browser storage is shared by every user who
signs in on that browser. Picking a language in the player's settings still
applies for the rest of the session.

The stored language is read asynchronously, so the first frame or two
(including "Loading...") can render in the device language, like the theme
preset.

`StartupSplash` and `StartupErrorApp` sit outside `ProviderScope`, so they
always follow the device language, whatever was chosen in settings.

## Guards

- `test/l10n/untranslated_text_test.dart`: no literal English under
  `convertedPaths`. The scanner has its own tests in
  `untranslated_text_scanner_test.dart`.
- `test/l10n/arb_consistency_test.dart`: every message has a description, and
  each translation uses only template keys and the template's placeholders, and
  every regional file has its base-language file. It checks keys,
  placeholders and base locales, not wording.
